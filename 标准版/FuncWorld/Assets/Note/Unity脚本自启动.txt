[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
这个特性,Unity编辑器中,场景完全为空就能靠代码这行启动.实测打包后依然有效.
核心机制是在 Unity 引擎完成底层初始化但尚未加载第一个场景(即“黑屏”或初始加载阶段)时,自动调用拥有特性标记的静态方法.
[RuntimeInitializeOnLoadMethod] ‌只能‌应用于‌静态、无参、无返回值的方法.

1. 在MOD中有效
MOD本质是将额外的程序集(Assembly/DLL)注入到游戏的运行时环境中.RuntimeInitializeOnLoadMethod的工作原理是Unity在启动时扫描‌所有已加载程序集‌中标记了该特性的静态方法.
程序集扫描机制‌:只要你的 MOD DLL 被成功加载到游戏的 AppDomain(应用程序域)中,Unity 的初始化系统就会像对待原生代码一样,扫描并注册你的初始化方法.
无需场景及GameObject‌:该方法不依赖场景和任何GameObject或MonoBehaviour组件,因此即使场景为空,或MOD没向场景中实例化任何对象,代码依然会执行.
2. MOD开发关键前提
虽然特性本身有效,但要让它触发,必须满足以下条件:
A. MOD DLL须在BeforeSceneLoad前被加载
这是最关键的一点.如果游戏的主程序在已经加载完场景、进入主循环后才加载你的MOD DLL,那么BeforeSceneLoad时机已经错过,你的方法将‌不会‌被执行.
有效情况‌:
使用‌BepInEx‌、‌MelonLoader‌、‌UnityDoorstop‌等主流MOD加载器.这些加载器通常在Unity引擎启动的极早期(甚至在main()函数执行初期)就介入,并将MOD DLL注入到域中.
在这种情况下,BeforeSceneLoad是完全可以触发的.
通过修改 Assembly-CSharp.dll 或使用 Harmony 补丁在早期入口点加载DLL.
无效情况‌:
MOD是通过游戏内的某个菜单按钮“动态加载”的(例如玩家进入游戏后点击“启用 MOD”),此时场景早已加载完毕,BeforeSceneLoad时机已过.
这种情况下,你应该使用AfterSceneLoad或者直接在加载DLL时手动调用初始化逻辑.
B. 程序集定义(Assembly Definition)的影响
如果你的MOD用了.asmdef文件,确保它被正确编译并包含在游戏能读取的路径下.Unity初始化扫描是基于程序集的,只要程序集被CLR加载,特性就会被发现.
3. 在MOD中使用该特性
在MOD开发中,BeforeSceneLoad是一个非常强大的钩子(Hook),常用于以下场景:
全局服务注册‌:初始化 MOD 的配置管理器、日志系统或服务容器(如 VContainer/Zenject 的手动绑定).
Harmony补丁安装‌:在场景加载前安装 Harmony 补丁,确保游戏原生代码在执行前已经被修改,避免竞争条件.
资源预加载‌:异步加载 MOD 所需的 AssetBundle 或配置数据,避免进入游戏后卡顿.
代码示例:‌
using UnityEngine;
using HarmonyLib; // 假设使用 Harmony
public static class ModInitializer
{
    // 在场景加载前执行,适合安装补丁和初始化核心逻辑
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    public static void OnBeforeSceneLoad()
    {
        Debug.Log("[MyMod] 正在初始化...");
        
        // 1. 安装 Harmony 补丁
        var harmony = new Harmony("com.example.mymod");
        harmony.PatchAll();
        
        // 2. 初始化配置
        ModConfig.Load();
        
        Debug.Log("[MyMod] 初始化完成.");
    }
}
4. 潜在问题
执行顺序不确定‌:多个MOD用了BeforeSceneLoad,那它们之间的执行顺序是‌不保证‌的,所以最好不要依赖其他MOD的初始化状态.
当需要顺序控制建议用SubsystemRegistration(更早期)或通过Harmony补丁在其他MOD初始化方法前后插入逻辑.
异常处理‌:若该方法中抛出未捕获异常,可能会致游戏启动崩溃或卡黑屏,务必添加try-catch块并记录日志.

总结:
无论编辑器运行、打包还是给游戏做MOD,‌[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]是有效的‌,前提是你要使用的MOD加载器(如BepInEx)能在游戏场景加载前将你的DLL注入到运行时中.
这是MOD开发中进行早期初始化的标准且推荐的做法之一.
